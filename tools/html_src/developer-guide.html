Developer guide

How Kagg2 is built and how to extend it. Companion files in the repository: ARCHITECTURE.md, GAME_DESIGN.md, PLAN.md, ASSETS.md, tasks.md, HANDOFF.md.

Build and run

cargo check                              # after every edit batch
cargo clippy --all-targets -- -D warnings
cargo test --release                     # 135+ tests, headless
cargo fmt
./run.sh                                 # release build + game
cargo run --release --bin texgen         # regenerate assets/textures (committed)
cargo run --release --bin playtest       # bots play every mission, win-rate tables (T30)
cargo run --release --bin server         # LAN server (T32); netclient is the text client
python3 tools/licence_check.py           # dependency/licence audit, writes LICENCES.md (T31)
tools/release.sh                         # checks + optimised build + dist/ archive (T31)

The crate is kagg2 (edition 2024, default-run = "kagg2"); dependencies are macroquad (with audio), png and glam. .cargo/config.toml sets target-cpu=apple-m1 on aarch64-apple-darwin only.

Determinism rules

  • The sim runs at a fixed 60 Hz (sim::clock). Same seed plus same commands gives the same World::state_hash.
  • Randomness comes only from sim::rng::Rng (xoshiro256**). No wall clock, no HashMap iteration in src/sim.
  • Mission timers use World::time, never real time.
  • Nothing under src/sim or src/board may import macroquad.

The sim step

World::step(&[Addressed]) -> Vec<Event>: controllers (AI, crew, autopilot) produce commands, commands apply, orbits move, missiles steer, ships integrate (docked ships are held), projectiles collide, upkeep runs, solid collisions resolve. Inputs are Commands addressed to a ship; outputs are Events that the scene turns into effects, sound and mission progress.

App flow

Boot -> MainMenu -> Briefing{m} -> Space{m} <-> Boarding{m} -> Debrief{m, won}
MainMenu -> Settings | Help          Debrief(win, m=10) -> Ending{chosen} -> MainMenu
Debrief(win) -> Briefing{m+1}        Debrief(loss) -> Briefing{m} (retry)

Only AppState::next(AppEvent) changes state. main.rs reads input per state, produces an event, and performs side effects around the transition (create the scene, save the game, rebuild the menu).

Mission engine (src/sim/mission.rs)

A mission is static data: Mission { stages: &[Stage] }, looked up with mission::def(id).

TypeMeaning
Stagetext (HUD objective, under 80 chars), goal, beats, protect: Option<(prefix, message)>, limit seconds (0 = none)
GoalThrottle, Target, Reach, DockAt, Scan, Cargo, Upgrade, Wait, Clear, ClearBut, Gone, Disabled, Board, Escort
Beatan Act at at seconds after the stage starts: Say(speaker, text) or Spawn(Spawn)
Spawnanchor (Player, in the player's frame; or Body(label)), offset, Role (Attack, Patrol, Drone, Ally, Hauler), class names, optional label override
MissionStateruntime: stage index, start time, next beat, notes, result. begin, update(world, events), on_boarding, board_wanted, take_notes, result
Carrycredits and upgrade levels carried between missions

Rules of the engine: stock sector enemies are removed in begin; a stage whose goal needs spawns (Clear, ClearBut, Gone, Disabled, Escort) waits until all its beats have fired; goals are checked every 6th tick; a Destroyed event whose label starts with the stage's protect prefix fails the mission; the player's death fails it from the scene.

Add a mission stage

static M3: [Stage; 2] = [
    stage("MINE 6 ORE - TARGET A BIG ROCK (T), PRESS K",
          Goal::Cargo { commodity: 0, qty: 6 },
          &[say(0.0, INGRID, "Load the hold first.")]),
    guarded(
        stage("CRIPPLE THE COURIER", Goal::Disabled("Courier"),
              &[spawn(0.0, Player, [-1500.0, 100.0, -3500.0], Role::Attack,
                      &["cutter"], Some("Courier"))]),
        "Courier", "THE COURIER WAS DESTROYED"),
];

To add a whole mission: add a static Mn, put it in MISSIONS (and raise app::MISSION_COUNT), add a Briefing and a verse pair in story.rs, route its sector in SectorId::for_mission. The test every_mission_is_defined_and_references_real_bodies checks that bodies named in goals and spawns exist in the sector.

Add a goal kind

Add a variant to Goal, handle it in MissionState::goal_met, decide whether it needs beats_done, and add a test using started(mission) and run(...) from the test module.

Boarding hooks

SpaceScene::boardable() asks MissionState::board_wanted(label); if the stage demands an objective it is put in BoardInfo.force and the objective screen shows only that. After the action apply_boarding calls on_boarding(label, objective, won && objective_done). Level themes by label are chosen in boardable() (Prison Barge, Courier).

Mission scripts

sim/script.rs parses the text format (documented in the manual) into the same Mission/Stage/Beat values. Strings and slices are leaked once (Box::leak) so the engine's &'static types did not have to change; scripts are tiny and loaded at start-up. register returns ids from 11; mission::def and SectorId::for_mission consult the registry for ids above 10. validate checks that named bodies exist in the sector. To add a goal or role to the format, extend Goal/Role first, then parse_goal/parse_spawn and the format table in the manual, with a test in script.rs.

Playtest bots and balance

SpaceBot::think(&mut World, goal) -> Decision turns the mission's current Goal into Commands (it is allowed to mutate the world only the way the dock screen does: purchases and services). It runs Helm, Weapons, Map and Science itself and leaves Engineering and Damage to crew AUTO, so the crew AI is exercised too. It keeps a stand-off range, never fires at a ship it must board once that ship is crippled, and never attacks the prey of a ClearBut stage. Decision.board asks the harness to start a boarding: playtest::run_mission builds the level with board::theme_for, plays it with board::bot::play_team and applies the result with sim::boarding::apply (the same function the game scene uses). BoardBot::act sets the player's yaw and pitch directly and returns an Input; it paths with a lock-aware breadth-first search, fights what it sees, detours for wanted pickups and returns to the airlock.

Workflow for a balance change: edit a constant in balance.rs (or mission data), run playtest 12 boarding and playtest 4, compare the tables, and write what you found in the commit or HANDOFF.md. Tests pin only the broad shape (a small level is won on Karl, harder difficulty never helps the bot, the sabotage fuse grows with the level, a party of two is not worse than a soloist); exact win rates are reported, not asserted. Set KAGG2_TRACE=1 to print goal, position and hull every 20 game seconds.

Multiplayer code

net::wire is a dependency-free binary codec: Writer/Reader (every read is bounds checked, floats must be finite), FrameBuf (length-prefixed frames, 256 KiB maximum) and the Command encoding; a test round-trips every command variant, so adding a Command means adding it to put_command/get_command and to net::station_of (the compiler enforces the latter). proto holds ClientMsg/ServerMsg and the Snapshot; bump PROTOCOL when the format changes. Server::poll (network) and Server::tick (one 60 Hz sim step plus snapshots) are separate so tests drive them by hand; Server::run is the wall-clock loop the server binary uses. Players hold stations; sync_crew sets the crew-AI flag of every automatable station nobody holds. Output goes through a per-client outbox (a client more than 4 MiB behind is dropped), so a slow client cannot stall the server. The integration tests in net/mod.rs run a real server and two clients over loopback TCP.

Co-op boarding code

BoardWorld.mates are extra Players. step_team(dt, &[Input]) gives each living member their input by swapping them into self.player for the per-player part of the step (with_player), then runs the shared parts (doors, rockets, monsters, objectives). Keys are shared after pickups. A monster targets nearest_player and hears the nearest of the step's noises. BoardScene creates one BoardBot per partner; a networked co-op boarding would feed human inputs into the same call.

Releases and licences

[profile.release] in Cargo.toml: thin LTO, one codegen unit, symbols stripped. tools/release.sh [target] and .github/workflows/release.yml are described in the manual. Cross-compiling needs the target's toolchain and linker; the Linux build needs X11, GL and ALSA development headers. tools/licence_check.py must pass before a release: add a crate with a new licence to its allow-list only after reading the licence.

Scene integration

SpaceScene::start_mission(id, &Carry, difficulty) sets world.difficulty, applies the carry, creates and begins the MissionState. Each fixed step: world.step, then mission.update, then events are handled. Notes (Note { who, text }) become 7-second captions; empty-speaker notes become messages. outcome() returns Some(won) 3 seconds after the mission is decided, or Some(false) when the ship has been dead 4 seconds.

Settings, bindings and saves

  • gfx/keys.rs: Bind enum (26 actions), Bindings (default keys, get/set/conflicts, text lines), a table of bindable keys. SpaceScene clones the bindings per frame and reads kb(Bind::X).
  • save.rs: formats are plain lines with a version header (kagg2-settings 1, kagg2-save 1). Parsing is tolerant: unknown lines ignored, values clamped. To add a setting: add a field, write it in to_text, read it in from_text, show a row in settings_ui.rs, apply it in main.rs. Bump the header version only for incompatible changes.
  • settings_ui.rs: rows 0 to 4 are fixed settings, then one row per Bind, then Reset and Back.

Add a rebindable key

Add a Bind variant, put it in Bind::ALL (and bump the array length in Bindings), give it a name and default_key, then replace the hardcoded key in space_scene.rs with kb(Bind::New). The key table in keys.rs must contain the default key (a test checks it).

Add a help page

gfx/help.rs: station text is in station(Tab) (first line is the title); menu pages come from pages(). Keep lines under about 60 characters; the pixel font is upper case.

Console and cheats

Parser and line editor: src/cheats.rs (Cheat, parse, Console, headless, unit-tested). Overlay and key handling: src/gfx/console.rs. Effects: SpaceScene::cheat, BoardScene::cheat (god mode tops up every frame, so the sim stays untouched), BoardWorld::kill_all, MissionState::force_win, and the level/board jumps in main.rs (mission::boarding_stage finds the boarding objective and ship). To add a command: add a Cheat variant and a parse arm, handle it in both scenes (or in main.rs), add it to HELP, and update the tables in the guide and manual.

Tests

Headless unit tests live next to the code. Useful helpers: mission::tests::started/run, combat::tests::spawn_ship, sector::new_game(seed, sector). Scene tests in space_scene.rs build a SpaceScene without a window (no drawing). Determinism tests compare state_hash of two runs.

Docs and versioning

After a task: update tasks.md (move the line to Done), HANDOFF.md, and whichever of GAME_DESIGN.md, ARCHITECTURE.md, ASSETS.md, PRD.json the change touched, then rebuild these pages with python3 tools/make_html.py. Bump Cargo.toml version: minor per finished task, patch per fix. Never edit Cargo.lock by hand.

Known gaps

  • Warp gates are not built; mission 6 is a plain blockade.
  • Minion stations are inert targets (no turrets, not boardable).
  • Warping mid-mission rebuilds the sector and loses mission spawns.
  • Balance is tuned with bots only (playtest); fun, sound and mouse feel are not verified by a human.
  • Multiplayer has no graphical client, no boarding or dock screen over the network, no encryption, no reconnect. Co-op boarding partners are AI in the game.
  • Script missions have no briefing, debrief or ending text; the leaked script data is never freed.
  • Linux and Windows release builds are only defined (script and CI workflow), not built here.
